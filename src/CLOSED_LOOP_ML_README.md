
# Camera-Informed Closed-Loop Pneumatic Separator

This folder extends the calibrated particle/dynamic separator with a first
digital-twin experiment for the question:

> **Can real-time knowledge of changing particle composition improve
> pneumatic separation compared with a fixed operating point?**

## Architecture

```text
true changing feed
       |
       v
synthetic feed camera
(material + projected size, with error)
       |
       v
state estimate
       |
       v
ML surrogate + adaptive controller
       |
       v
high-pulse airflow + duty cycle
       |
       v
existing dynamic separator physics
       |
       +----------------------+
       |                      |
       v                      v
 top/light stream          heavy stream
       |
       v
synthetic outlet camera
       |
       +------ feedback to next control window
```

## Important scientific separation

### Ground-truth plant
The existing `DynamicSeparatorSimulation` remains the plant. It contains the
true simulated particle size, effective density, coating state, and suspension
velocity.

### What the controller sees
The controller is **not** allowed to read those hidden states. It sees only:

- camera-estimated material class;
- camera-estimated projected size;
- previous top-stream camera composition.

The default synthetic camera has intentional material-classification errors
and 4% relative size-measurement noise. These are simulation assumptions that
must eventually be replaced by validation data from a real vision system.

### Machine-learning model
`HistGradientBoostingClassifier` is trained on data generated by the existing
dynamic separator over a bounded range of airflow and duty-cycle settings.

Inputs:

- estimated suspension velocity;
- particle size;
- high-pulse reference velocity;
- duty cycle;
- low/high pulse fraction.

Output:

- probability of `light`;
- probability of `heavy`;
- probability of `active`/unresolved.

The controller estimates suspension velocity from camera material + size using
the calibrated feed population. It never receives the true particle suspension
velocity.

## Control variables

Version 1 changes:

1. high-pulse volumetric airflow;
2. pulse duty cycle.

Pulse frequency is held at 4 Hz for the first experiment so we can answer the
composition-feedback question before adding another control degree of freedom.

The candidate control search is restricted to ±20 m3/h around Zhu's
size-class-specific reference flow and duty cycles of 0.35, 0.45, 0.55, 0.65.
These are engineering search bounds, not claimed literature optima.

The previous top-stream camera measurement is also used as feedback. If
estimated Cu contamination in the top stream is too high, the next control
window reduces the high-pulse airflow by one step.

## Changing feed experiment

The simulation creates a sequence of identical underlying particle populations
whose **Al/Cu mixture changes with time**. The exact same true sequence is run
twice:

### Fixed control
- Zhu reference high-flow setting;
- duty = 0.50.

### Camera-informed adaptive control
- noisy feed-camera observation;
- ML surrogate predicts candidate outcomes;
- controller chooses flow + duty;
- noisy top-camera observation provides feedback for the next window.

This is the direct A/B test needed to evaluate whether real-time composition
information has value.

## Objective

The first balanced control objective is:

```text
0.30 * Al recovery to light
+0.30 * Cu recovery to heavy
+0.18 * Al purity in light
+0.18 * Cu purity in heavy
-0.04 * unresolved fraction
```

The weights are **project choices**, not literature measurements. They are
explicit so sensitivity studies can change them.

## What would count as evidence that real-time knowledge helps?

A useful first signal is:

```text
mean adaptive objective > mean fixed objective
```

on the **same changing true feed sequence**.

More convincing evidence requires:

1. repeated Monte Carlo seeds;
2. multiple amplitudes/rates of composition change;
3. camera-accuracy sensitivity;
4. controller-weight sensitivity;
5. hardware-calibrated valve-flow response;
6. experimental camera confusion matrix;
7. experimental validation of separator trajectories.

The current model is therefore a hypothesis-testing digital twin, not a claim
that the controller is already plant-ready.
